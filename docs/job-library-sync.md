# 从 GitHub 增量同步职位库

在控制台的“职位库”中点击“从 GitHub 增量同步”，即可读取
[`keii-2596/job-autopilot`](https://github.com/keii-2596/job-autopilot) 的公开 `data/jobs.json`。
只导入标记为 **2027 届 + 秋招或秋招提前批** 的岗位，不需要登录白瓜，不运行爬虫，
也不需要重启网页或暂停当前 Codex 任务。

## 如何同步

先检查职位快照的最近提交。数据版本未变时不重复下载或写入；版本变化时下载固定提交的
完整公开快照，在本地按岗位标识比对，只新增或更新有变化的记录。
因此“增量”指数据库合并，并非远程提供了逐条增量接口。
历史导入标识不同但公司、职位名和公告或投递链接相同且唯一时，会复用原有岗位。

界面显示检查、下载、合并、完成或失败状态，以及新增、更新、未变和保留本地内容的数量。
同一个岗位可能更新了公开字段、同时保留其他本地字段，因此“更新”与“保留”计数可能重叠。
失败可重试；成功后自动刷新职位列表，不改变当前筛选条件。

## 保护本地数据

- 只允许导入公开岗位字段；忽略快照中的内部 ID、备注及其他未允许字段。
- 不上传或覆盖个人资料、简历、登录凭据、投递记录和本地备注。
- 记录每个岗位上次成功同步的公开字段，远程后续变更仅在本地字段未被另外修改时应用。
- 首次同步能识别本地较新的记录时优先保留本地内容；没有可比较时间时按公开快照合并。
- 远程消失的岗位不删除；匹配到多个本地岗位时跳过并计入保留数量。
- 数据、合并基准和成功版本在同一事务中提交。失败不推进成功版本，也不会留下半批导入。
- 使用固定仓库、提交与文件摘要校验，远程历史回退或分叉时停止同步。
- 不展示包含用户凭据的 HTTP 链接；历史快照中误写成此类链接的邮箱投递信息会被忽略并提示。

## 自动同步

默认关闭。开启“自动同步职位数据”后，网页后台运行期间每 6 小时检查一次；
退出后台或电脑休眠时不运行，恢复后补做到期检查。关闭网页标签页不影响仍运行的后台。
关闭开关会取消尚未开始写入的自动请求，已经进入事务的合并会安全完成。

此开关与“插件自动更新”互相独立：一个同步岗位数据，一个更新程序代码。
数据同步不会安装代码；代码更新期间不能同时导入岗位，代码更新也会等待数据同步结束。
原有本地每日爬取任务不受此功能影响。
