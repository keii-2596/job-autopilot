# 从 GitHub 更新

在控制台左侧打开“插件更新”。“检查更新”查询固定仓库
[`keii-2596/job-autopilot`](https://github.com/keii-2596/job-autopilot) 的 `main` 分支，
展示远程提交与说明；“安装更新并重启”将远程新增改动合并到本地插件源目录，
通过 Codex 本地插件市场重新安装，并重启网页后台。

## 自动更新

- 默认关闭。开启开关代表允许安装该仓库后续发布的代码。
- 网页后台进程运行时，每 6 小时检查一次。关闭网页标签页不影响仍在运行的后台；退出后台或电脑休眠期间不运行，恢复后补做已到期的检查。
- 发现新版但求职任务正在执行或等待回答时，不会打断任务。自动模式在任务空闲后重试；手动模式需要稍后再点“安装更新”。
- 关闭开关会阻止尚未开始安装的自动请求。已经进入安装过程则先完成或恢复，避免停在半写入状态。
- 更新后网页会尝试重连；若仍显示旧页面，手动刷新。新版技能和工具在新 Codex 对话中使用。

## 更新边界

### 为什么会等待任务

GitHub 更新不需要连接 Codex。“Codex 按需连接”表示发送指令时才连接模型，
不等于网页后台掉线。当前网页任务已暂停、已完成或已停止时，可以安装更新。

更新页会列出具体阻挡项：

- 当前 Codex 任务正在启动、执行、等待回答，或正在切换连接：先处理确认项或暂停当前任务。
- 职位数据正在同步：等待同步结束，不中断数据事务。
- 其他对话的历史活动仍标着运行或等待：显示“核实历史任务”，不声称该任务真的还在执行。
  先在原对话核实任务已停止，再点“确认原任务已停止”。它只整理本地活动记录为暂停，
  不会中断模型、删除历史、修改投递结果或个人资料。原任务若仍运行，请勿确认。

网页后台重启会整理本控制器遗留的网页活动；已被替换的旧网页请求也不再阻挡更新。
其他对话的记录不靠“多久没更新”自动判定失效，也不会被批量静默清理。
整理操作绑定该活动最新事件编号，旧页面不能清理刚刚恢复或发生新进展的任务。

阻挡解除后页面会恢复可安装状态。自动更新关闭时需要再次点击安装，不会偷偷排队安装；
开启时则在下一次空闲检查重试。更新准备完成后、写入文件前也会再次核对任务状态。

### 安装范围

仅支持通过本机默认插件市场安装、且来源为本地目录的 Job Autopilot。
安装时使用本机 `plugin-creator` 提供的校验、版本缓存刷新和重新安装流程。
缺少这些工具或安装来自远程市场时会提示人工处理，不会更改市场配置。

更新跟踪提交而非只比较版本号。“本地基准提交”是已经合并的上游基准；
本地可能另有尚未发布的功能，因此“远程暂无新提交”不意味着本地与 GitHub 文件逐字相同。
首次基准是 `dd36cd051505884c57f70ecc71c6b7417c38df95`，之后随成功安装更新。
远程历史回退或分叉时停止自动更新，不自动降级。

先下载基准与目标提交的固定快照，再进行三方合并：

- 仅处理远程改动过的公开插件文件。本地独有文件不删除。
- 本地爬虫文件排除在更新范围外；共享文件里的本地改动尝试保留，有冲突则整个安装不开始。
- 个人资料、投递记录、登录凭据和本地职位数据库不属于更新包，也不会上传。
- 仓库里的公开职位快照可以随代码更新；不会用它覆盖已有本地数据库。已有职位库使用独立的[职位数据增量同步](job-library-sync.md)入口更新。
- 安装前在本地状态目录的 `updates/backup-*` 中保存源文件备份和 `restore.json` 清单。
- 校验或重新安装失败时恢复本次改动的文件。若检测到文件被另一个进程再次修改，不覆盖它，并提示人工恢复。

不自动清理备份。断电或强制结束进程等非正常中断可能需要按备份清单人工恢复，
界面会显示中断状态，不会把未完成的更新报告为成功。

## 安全与测试

不需要 GitHub 密钥。仓库和分支固定，不接收任意下载地址。
更新入口只接受本机来源与专用请求头；下载包拒绝目录穿越、符号链接和超限内容。
这是对可信项目源代码的更新授权，不保证远程代码不存在缺陷。

测试使用临时源目录、数据库和模拟远程快照，覆盖路径检查、三方合并、冲突保护、
安装失败恢复、任务忙碌延后、自动更新开关与请求来源限制，不对真实投递任务执行更新测试。
