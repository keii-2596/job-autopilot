# 首次配置与常见问题

[返回首页](../README.md)

先把网页打开，再按需要接通 AI、浏览器和手机。不必为了浏览职位库一次装齐所有工具。

## 安装插件并打开网页

推荐使用有本地插件功能的 Codex 桌面端，先确保你能正常和 Codex 对话。当前项目在 macOS 上验证；Linux 和 Windows 环境尚未在本项目中完整验证。

1. 将[首页的安装请求](../README.md#已经在用-codex让它帮你安装)发给 Codex。它需要下载这个已有仓库，将其注册为本机个人市场中的插件，再安装。
2. 核对仓库是 `keii-2596/job-autopilot`，按提示处理安装权限。这个仓库不是一个预先配置好的公共插件市场，不能直接把仓库链接当作 `codex plugin add` 的参数。
3. 安装后新开一个任务，发送「打开 Job Autopilot 控制台」，使用它返回的本机地址。
4. 看到「职位库」「投递记录」「个人资料」等入口后，就可以准备资料。默认端口是 `8765`；如果由 Codex 选择了其他端口，以实际返回地址为准。

这里使用的是 OpenAI 官方文档描述的[本地插件市场与 Plugin Creator 工作流](https://learn.chatgpt.com/docs/build-plugins)，不是本项目已上架公共目录的承诺。若你的 Codex 找不到 Plugin Creator 或不支持本地插件，先更新或检查 Codex 配置；仍可以按[首页命令](../README.md#想先看看界面和职位库直接启动网页)体验网页与职位库。

## 按需配置

| 想使用的功能 | 需要准备 | 暂时没准备好时 |
| --- | --- | --- |
| 打开控制台、浏览职位、手动维护资料和记录 | Python 3.9+；用首页命令下载时还需要 Git | 无需 Codex、JDWatch、手机或白瓜登录。网页资源已随仓库提供，无需另外构建前端。 |
| 网页直接对话、AI 解析简历 | 已登录、支持 App Server 的本机 Codex CLI；Job Autopilot 插件已安装并可用 | 网页仍可浏览，但不能执行 AI 任务。让 Codex 检查本机命令、登录状态和插件安装情况。 |
| 打开招聘网站、登录、填写和上传 | 当前执行任务中的 Codex 能调用浏览器工具，并获得所需权限 | 暂停网站操作；这个插件本身不附带独立浏览器。 |
| 通过 JDWatch 补充查岗 | 安装 `@jdwatch/cli`，按它的授权流程登录 | 不影响查看内置职位库。当前技能的找岗／投递检查也可能要求 JDWatch 授权，按任务提示完成后再继续。 |
| 读取 PDF 简历文本 | 本机有 `pdftotext`，可由 Poppler 提供 | 可先用 DOCX、TXT 或 Markdown；扫描图片型 PDF 需要先转为可读取的文本。 |
| Android 短信验证码辅助 | 已安装 ADB，手机开启 USB 调试并授权这台电脑；还要有本次操作授权 | 其他功能仍可使用；遇到需要新短信登录的网站时，流程会提示连接手机或由你接手。iPhone 不支持 ADB。 |

不要在聊天、Issue 或公开配置中粘贴访问密钥。JDWatch 授权应在它提供的本机授权流程中完成。

## 用简历建立资料

1. 打开「个人资料」，在「用简历生成个人资料」中输入文件的**完整本机路径**，例如 `/Users/your-name/Documents/resume.pdf`。当前入口是文件路径，不是文件上传框。
2. 点击「AI 解析简历」。页面会显示任务状态、AI 回复和需要你处理的确认项；出现「请求已发起」不代表解析已经完成。
3. 等候选字段出现后检查内容，修正不准确的信息，再确认写入。AI 没有读到的信息不要让它猜。
4. 补充求职方向、城市、排除项和简历路径。以后公司的新字段需要你确认后，才能作为合适范围内的可复用答案。

首次建议先完成这一步，再让 AI 投递。PDF 提取失败时先检查是否为扫描件，以及本机是否能运行 `pdftotext`。

## 从哪里发起任务

- **网页**：进入「概览」，直接发消息或点击快捷按钮。运行中显示「追加指令」；空闲时发送会启动新一轮。消息自动带上 `$job-autopilot`。
- **Codex 对话**：发送「使用 `$job-autopilot`，按我的偏好找岗位，先给候选，不提交」。这个任务的阶段进展会同步到同一数据目录下的控制台。

「授权本次」仅在有对应权限请求时可用，不是永久授权开关。需要填写答案或确认投递时，先看清具体问题再处理。

## 常见问题

### 网页打不开

先确认启动控制台的进程仍在运行，并使用启动时显示的地址。只打开 `index.html` 文件不能代替启动后台。

如果默认端口已被占用，在仓库目录运行：

```bash
./scripts/job-autopilot serve --port 8877
```

然后打开 [http://127.0.0.1:8877/](http://127.0.0.1:8877/)。不要同时启动两个后台处理同一轮任务。

### 显示「Codex 按需连接」或没有连接

「Codex 按需连接」通常表示当前没有执行 AI 任务，发送消息时才会连接；它不妨碍浏览职位或从 GitHub 同步数据。

若页面提示整个网页后台连接失败，先恢复本机服务，再刷新。若只有 Codex 连接失败，按错误提示检查本机 Codex 登录和可用性。两种连接不是一回事。

### 桌面提示「已在另一个应用中打开」

同一任务不能同时由网页后台和桌面接管。先在网页点击「移交桌面」，它会暂停当前轮次并释放任务；再到桌面点击「重试」。不要为了切换界面新建一份重复投递任务。

### 为什么更新一直在等待任务

查看「插件更新」列出的阻挡项。真正运行中的任务应先暂停或完成；如果是其他对话的历史记录，先到原对话核实已经停止，再按页面提示整理记录。不要因为长时间没变化就认定它停止了。详见[更新阻挡说明](plugin-updates.md#为什么会等待任务)。

### 有些记录看起来是实习，或者不是具体岗位

职位库按来源的届别和招聘批次标签筛选，不是人工核验过的逐个职位清单。综合公告可能同时包含多种机会。让 AI 在实际投递前核实官网的岗位、毕业时间要求、地点和截止日期，并明确排除实习。

### 我只想更新岗位，不想更新插件

在「职位库」点击「从 GitHub 增量同步」。它不会安装代码或上传个人资料；自动同步和插件自动更新是两个独立开关。详见[职位同步说明](job-library-sync.md)。
